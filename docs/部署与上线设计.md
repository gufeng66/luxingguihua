本文件区分已经跑过的检查和还没做的公网改造。没有购买服务器，也没有对公网开放。

交付状态：代码与离线验收完成，真实服务验收待执行。费用上限未确认，不用付费模型做并发或整批真跑。

## 已验证

这些是本轮在本机跑过的，不是线上经验。

- 无 `--reload` 的单进程可以启动，`GET /api/health` 不访问外部网络。
- 必需配置缺失时，`planner.preflight.missing_config` 只列出 `OPENAI_API_KEY` 或 `AMAP_WEBSERVICE_KEY`，不输出密钥值。`.env` 里已经有这两项时，命令行检查显示已就绪。
- 页面和普通日志字段是 `plan_id`、阶段、耗时、状态、错误类别、用量。不记录请求头、完整提示词和原始工具响应。
- `plan_id` 写在方案记录里，日志按它关联。
- `GET /api/ready` 把「配置缺失」和「MCP 的 HTTP 不可达」分开。配置缺失则未就绪。MCP 不可达时应用仍就绪，并标降级。HTTP 可达不等于工具调用可用。
- 备份 `plans.db` 后再读，记录还在。旧行显示「未记录核实状态」。
- 同时规划默认 2 个。两个名额被占住时第三个得到 HTTP 429，用屏障测试，不用睡眠碰运气。名额在正常结束、澄清、异常和响应还没被消费时都能释放，重复释放无效果。
- SSE 空闲时发送注释心跳 `: ping`。断连检查在心跳等待之外继续跑。

## 仅设计

- 反向代理需要关掉 SSE 缓冲。代理超时要盖住工作预算和收尾，不能只盖住 240 秒的工作段。心跳和断连取消也要穿过代理。本轮没有安装反向代理。
- `/results/旅游规划-…-{uuid}.md` 与 `/results/maps/{uuid}.html` 已由固定文件名/UUID 校验和 API 认证的私有路由提供；快照、SQLite 数据库和辅助文件没有 HTTP 路由。真实浏览器分支仍待按 `evals/MANUAL_BROWSER_ACCEPTANCE.md` 留证。
- 进程内的 MCP 连接已经按请求创建和关闭。内存限流和并发名额仍然不跨进程。单实例不够时再考虑共享限流、产物存储和数据库迁移。
- 只有断线后仍要继续执行，才引入任务持久化和重连。当前断线会取消这次规划。
- 监控定义为延迟、流程正常完成率、可靠完成率、降级率、工具失败率、用量和 429 次数。流程完成看 `finished`。可靠完成只看 `quality.status == complete`。
- 回滚要记下版本、配置、备份和旧库兼容性。先备份再回退。

## 公开上线前必须补齐

- 反向代理、超时和 SSE 缓冲的实际配置，以及一次从浏览器经过代理的断连取消。
- 两个 iframe 分支、认证、沙箱隔离与竞态的真实浏览器证据；受控读取代码已实现，但尚未替代真机证据。
- 多进程下的名额、限流和产物存储。当前实现只保证一个进程。
- 费用上限确认后的真实评测：设置 `GOLDEN_LIVE_APPROVED=1` 和正数 `GOLDEN_COST_LIMIT_USD` 后，按 `evals/integration_matrix.json` 执行。运行器会记录 `blocked`、失败、超时与无终态；跨城首场失败后，后续场景标为 `blocked_by_previous_failure`。
- 监控采集。上面的指标目前只是定义。
