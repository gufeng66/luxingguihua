## B3 票务复用状态机（评审第 4 条）

### 三元并存

```python
ticket_reuse = {
    "parent_reason": "unavailable",   # 父快照原始值，不覆盖
    "parent_class": "failed",         # ok | skipped | failed | unknown
    "reuse_source": "parent_failed",  # parent_ok|parent_skipped|parent_failed|parent_reused|parent_unknown
}
```

纯函数放 `planner/routing.py`（**不新建 `reuse.py`**）：

```python
def classify_ticket_parent(parent_reason: str) -> tuple[str, str]:
    """返回 (parent_class, reuse_source)。"""
```

映射：`ok→("ok","parent_ok")`；`skipped→("skipped","parent_skipped")`；`unavailable/missed/timeout→("failed","parent_failed")`；`reused→("ok","parent_reused")`；其他/空→`("unknown","parent_unknown")`。

### 正文文案优先级（`ticket_markdown`）

1. `reason == "skipped"` → 「本次未查票（无需铁路）。」
2. `reuse_source=="parent_failed"` → 按 `parent_reason` 细分：`unavailable` 服务不可用/依赖缺失、`missed` 未调度或空结果、`timeout` 超时，均写「本次未重新查询，余票未知」。
3. `parent_reused` → 「沿用更早一次查询（时间 X），余票未刷新。」
4. `parent_ok` → 「上次查询结果，未刷新（查询时间 X）。余票不是当前余票。」
5. 兜底 → 「本次未重新查询，余票状态未知。」

三处复用分支（`pipeline.py:1364-1427`、`:1499-1536`、`:1537-1568`）抽唯一构造器 `_reuse_state()`，消除重复；`ticket_context` 必须传 `reason` 与 `reuse_source`（现在漏传 `reason`）。

### 状态规则表

| 父状态 | 正文可否写「余票未刷新」 | 应写 |
|---|---|---|
| `ok` | 可以 | 上次查询结果，未刷新（带时间） |
| `reused` | 可以，带原查询时间 | 沿用更早一次查询 |
| `skipped` | 不可以 | 无需铁路 |
| `unavailable` | 不可以 | 服务不可用/依赖缺失 |
| `missed` | 不可以 | 未调度或空结果 |
| `timeout` | 不可以 | 超时 |

### SSE 与告警

- 复用分支 step 改为 `reason="reuse_parent"`（ticket 与 map 同码）。
- 新码三处登记：`frontend/app.js reasonText()`、`evals/run_golden.py`、`README.md`。
- 父级失败复用额外 `warning code="ticket_reuse_parent_failed"`。

### 持久化

快照新增 `ticket_reuse`；`parent_reason` 仍取快照 `ticket_reason`，另传 `parent_class`；旧 v4 快照无该字段时按 `parent_unknown` 兼容读取。

## B4 三层路由语义（评审第 5 条）

`_NO_MAP`（17 条）拆三组：

```python
_NO_MAP_ARTIFACT = ("不要地图","不用地图","不需要地图","无需地图","不生成地图",
                    "不要路线图","不用路线图","不需要路线图","无需路线图")
_NO_ROUTE = ("不查路线","不查交通","不排路线","不要查路线","不用查路线",
             "不需要查路线","无需查路线","不要路线查询","不用路线查询",
             "不需要路线查询","无需路线查询","不要交通耗时","不查交通耗时")
_NO_POI = ("不要找景点","不用找景点","不需要找景点","无需找景点",
           "不要景点","不需要景点","不用搜景点","不搜景点")
```

- `_NO_MAP_ARTIFACT` 只否决地图 HTML 产物，`need_poi_search` / `need_route` 仍为 True。
- `_NO_ROUTE` 只否决路线耗时查询（高德路线查询），`need_poi_search` / `need_map_artifact` 仍为 True。
- 刻意不收「不要路线」这种宽泛子串：它会误撞「不要路线图」，把「不要地图」误判成「不要查路线」，因此词表只收明确带「查 / 排 / 查询 / 交通耗时」动作的说法。

新纯函数 `map_scope(query) -> dict`（保留 `skip_map_reason()` 薄封装）：

| 用户表达 | need_poi_search | need_route | need_map_artifact | reason |
|---|---|---|---|---|
| 不要地图 / 不要路线图（路线图是 HTML 产物，不是路线耗时查询，`need_route=是`） | True | True | False | `user_no_map` |
| 不查路线 / 不排路线 / 不查交通耗时（`_NO_ROUTE`） | 是 | 否 | 是 | `user_no_route` |
| 不要找景点 / 不要景点 / 不搜景点 | False | False | False | `user_no_poi` |
| 没说明 | True | True | True | `""` |

- 「不要路线图」说的是不要那张 HTML 图，**不等于**不要查路线耗时；只有明确说「不查路线 / 不排路线 / 不查交通耗时」才关掉路线耗时查询。两种否决并存时 reason 取更直观的 `user_no_map`，但 `need_route` 仍如实为 False。
- `need_route=False` 时：景点候选与结构化行程仍保留，不发出任何路线 HTTP 请求，所有相邻段标记为 `not_queried`、耗时与到达时刻保持 `unknown`，质量状态为 partial / `travel_time=unverified`。
- `route_source ∈ {"built","reused","none"}` 显式枚举：父行程存在且票务未变 → `reused`；本次真排程 → `built`；都没有 → `none`，行程表走确定性降级文案，**不得**让模型自由生成当作已有行程。
- `map_only` 不再「不强制」：`need_map_artifact` 由 `map_scope` 决定，行程来源用 `route_source`。
- 新码 `user_no_poi` 三处登记；`evals/test_routing.py:132-134` 两条断言按新语义改。

## B5 结构化事实闸门（评审第 3 条）

### 白名单结构（`planner/summary.py`）

```python
{
  "days": {1: {"date": "...", "poi_order": [...],
               "legs": [{"from": "...", "to": "...", "duration_minutes": 12,
                         "status": "reference|unknown"}]}},
  "sight_names", "lodging_names", "station_names",
  "unselected_names", "unlocated_names", "must_visit_names",
  "durations": {(from, to): minutes},
  "date_unknown": bool,

```

字段来源已核实：legs 只有 `origin_id/dest_id/mode/duration_seconds/depart/confidence`，**没有 distance**（`distance_meters` 只预留为空，不参与校验）；`confidence ∈ {reference, unknown}`。

### 四类检查 `poi_gate_issues(answer, whitelist, *, plan_ready)`

1. **名称**：景点级名称命中 `unselected_names`/`unlocated_names`/`station_names` → `poi_not_in_itinerary`。
2. **顺序**：「景点建议」里 `第N天` 单调，同日景点顺序是 `poi_order` 子序列。
3. **耗时**：`(\d+)\s*分钟` 必须能对上同一天某条边的 `(from,to,duration)`，或落在 items 的 `start–end` 差内；`unknown` 边不得写成确定分钟 → `travel_time_overclaim`。
4. **状态**：`reference` 边不得写成「已核实/实测/确认」；`date_unknown` 时不得出现具体日期 → `date_overclaim`。

### 职责（评审 3.4）

- 模型只写说明；车票/预算/行程表/需求摘要/注意事项 已由 `_apply_structured` 确定性替换。
- 新增 `sights_suggestion_markdown()`：命中 issue 时**整段确定性替换**「景点建议」，再二次校验；`degraded_plan` 复用同一生成器。
- `map_summary_block` 的 `ok` 分支不再无条件回传 `map_context` 原文，改传结构化摘要 + 白名单名称清单，证据链接只经 `safe_evidence_url`。

`cancel → drain(记录残留) → 判定 → close MCP → 报告`：

- `subruns.drain()` 返回未结束任务名；`iter_agents` 汇总 `cleanup`。
- 窗口内仍有残留 → `subagent_leak=True` + 任务名；仍执行 `close_ticket_agent()`（否则真泄漏），同时记 `mcp_closed_after_timeout=True` 并告警 `code="subagent_leak"`；**不宣称资源已完全释放**。
- drain 用 `asyncio.shield()` 包住，防二次取消跳过清理。
- 工具级超时：`RecordingTool.ainvoke` 加 `wait_for`；`collect_candidates_async` 每个 httpx 请求加 `httpx.Timeout`；`to_thread` 路径套 `wait_for` 并标记 `abandoned`；取消事件在 await 前检查。

- 测试全部 mock（`stream_plan`/`_probe_mcp`/`is_disconnected`/LLM/工具），**不得触网**。

5. **`_plan_without_date` / `_date_unknown_item` 加在 `planner/map_fallback.py`**：`ensure_route_map`（历史兜底路径）走 `_date_unknown_schedule` 时会得到 `tasks == []` 并静默不写 HTML，需要按无日期方案重新分配候选后再 `days_to_tasks`。
6. **`server.py` 必须在 `event_source()` 生成器内预设同一个 `RunStats`**：`planner/async_utils.py::watch_aiter` 用 `asyncio.create_task(agen.__anext__())` 驱动每一帧，`create_task` 会复制当前 context。实测若只在生成器首帧里 `begin_run_stats()`，第二帧 `current_stats()` 就是 `None`，深层子任务的 `note()` 会全部静默丢弃。因此 `server.py` 自己持有 `request_stats`，在 `event_source()` 里 `begin_run_stats(request_stats)`，并显式 `run_stats=request_stats` 传给 `stream_plan`；总超时、断连由这一层直接 `request_stats.note("sse", ...)`，不依赖 ContextVar。
