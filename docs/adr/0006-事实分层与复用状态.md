# ADR-6 事实分层与复用状态

- 状态：已采纳
- 日期：2026-11-12
- 适用范围：当前 `stream_plan` 主路径（`planner/pipeline.py`、`planner/routing.py`、`planner/summary.py`、`planner/quality.py`）。`planner/dispatch.py`、`planner/backends.py` 与 `amap-lbs-skill/` 属历史实现，不受本决策约束。

## 背景

一次审查发现三类话术在控制层是「允许被说出口」的：

1. **复用把失败说成未刷新。** 复用轮的面子状态是 `reused`，`ticket_markdown` 按 `reused=True` 走到「上次查询结果，未刷新」。父方案那次查询其实是 `unavailable` / `missed` / `timeout` 时，正文照样说「沿用上次查询」，读起来像「上次查到了，只是没刷新余票」。
2. **复用的复用把原因彻底丢掉。** 父方案自己也是复用时，它的快照里 `ticket_reason` 已是 `reused`。孙代读到的 `parent_reason` 就是 `reused`，最初那次查询到底怎么样，已经没有任何地方记得。
3. **地图文件存在被当成「地图事实可信」。** 成文闸门只校验六章节和车次号正则，景点名、游玩耗时、先后顺序完全没有约束；同时 `map_summary_block` 的 `ok` 分支把整段 `map_context`（含行程 Markdown 与证据链接）原样交给模型。

## 决策

### 1. 复用状态三元并存

复用轮同时保留三个字段，谁也不顶替谁：

| 字段 | 语义 | 存放 |
|------|------|------|
| `parent_reason` | 父方案那次查询的**原始结论**（`ok` / `skipped` / `unavailable` / `missed` / `timeout` / `reused`），从不改写 | 快照 `ticket_reuse.parent_reason`；质量侧 `ticket_state.parent_reason` |
| `parent_class` | 给质量聚合用的分类（`ok` / `skipped` / `failed` / `unknown`） | 质量侧 `ticket_state.parent_class` |
| `reuse_source` | 面向正文与前端的那一层（`parent_ok` / `parent_skipped` / `parent_failed` / `parent_reused` / `parent_unknown`） | 快照 `ticket_reuse.reuse_source`；正文措辞 |

取值统一由 `planner/pipeline.py` 的 `_reuse_state()` 构造，三处复用分支共用，避免正文、质量结论与 SSE step 三处说法互相矛盾。`classify_ticket_parent()` 是纯函数，只做分类，**从不改写父原值**。

文案优先级固定：父 `skipped` → 「本次未查票（无需铁路）」；父失败（`unavailable` / `missed` / `timeout`）→ 「上次查询失败（原因细分），本次未重新查询，余票未知」；父 `reused` → 「沿用更早一次查询（查询时间 X），余票未刷新」；父 `ok` → 「上次查询结果，未刷新（查询时间 X）」。

### 2. 复用轮用独立 step 码

复用分支既没连票务也没跑地图，`ticket` 与 `map` 两个 step 统一发 `reason=reuse_parent`，不写成 `route_no_rail` / `route_no_map`。那两个码的含义是「本轮判定不需要」，与「完整沿用上一版」是两件不同的事；混用会让前端和黄金集把复用读成路由跳过。

### 3. 地图判断拆三层

`map_scope()` 返回 `need_poi_search` / `need_route` / `need_map_artifact`。规则：

| 用户说法 | 检索 | 行程 | HTML 产物 |
|----------|------|------|-----------|
| 不要地图 / 不要路线图（只否决 HTML 产物，路线耗时仍查） | 是 | 是 | 否 |
| 不查路线 / 不排路线 / 不查交通耗时（`_NO_ROUTE`） | 是 | 否 | 是 |
| 不要找景点 / 不要景点 | 否 | 否 | 否 |
| 没说明 | 是 | 是 | 是 |

「不要路线图」说的是不要那张 HTML 图，不等于不要查路线耗时；只有明确说「不查路线 / 不排路线 / 不查交通耗时」才关掉路线耗时查询。`need_route=False`（`user_no_route`，或与「不要地图」并存取 `user_no_map`）时景点候选与结构化行程仍保留，不发出任何路线 HTTP 请求，所有相邻段标记为 `not_queried`、耗时与到达时刻保持 `unknown`，质量状态为 partial / `travel_time=unverified`。

行程来源另记 `route_source`：`built`（本轮真排程）/ `reused`（完整沿用父方案）/ `none`（没有可信结构化行程）。用「含混的布尔」代替它，会把「模型自由生成」当成「need_route=True 的结果」。

### 4. 事实替换在前，闸门在后

有结构化行程时，「景点建议」由 `sights_suggestion_markdown()` 用 `days` 确定性生成，与「行程表」「车票建议」「预算」一样整节替换；`poi_gate_issues()` 只做最后检查（景点名分池比对、顺序单调、耗时只能引用当天结构化边、`reference` 不得写成已实测、无结构化行程不得断言具体景点）。

不让自然语言闸门承担事实替换：闸门是词表与子串匹配，绕过它比绕过确定性生成容易得多。

## 后果

- 快照多 `ticket_reuse` 一个字段；旧快照没有它时按 `parent_unknown` 兼容，不会凭空断言成功。
- `ticket_markdown()` 新增 `reuse_source` / `parent_reason` 两个带默认值的关键字参数，旧调用方零改动。
- 闸门会误报，也可能漏检（简称、错别字、候选内子景点、「约半小时」这类非整数耗时都不解析）。这些漏检记录在 `ARCHITECTURE.md` 的「成文闸门与结构化事实」一节，不假装已覆盖。
- `reuse_parent` 需要前端 `reasonText()` 与黄金集的 `need_map` 反推集合同步登记；新增 step 码必须同时改这两处。

## 未采用的做法

- **让 `build_ticket_agent()` 缺依赖时返回 `(None, tools)`**：与 `planner/ticket_cache.py` 的 `spec, client = await build_ticket_agent(...)` 解包冲突，且会让调用方拿到半成品 spec。改为抛 `TicketBackendUnavailable`，由 `get_ticket_agent()` 捕获并记 `dependency_missing` 诊断。
- **把 `parent_reason` 直接改写成分类值**：会二次丢失原始结论，孙代就无法再区分「最初查失败」与「最初没查」。
- **只加 `need_route` 而不拆 `need_poi_search`**：会出现「用户说不要找景点，系统仍然检索并生成具体景点」。
